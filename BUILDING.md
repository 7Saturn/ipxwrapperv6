# Building IPXWrapper

This document explains how to set up a build environment and how to compile
IPXWrapper, on Linux (cross-compiling for Windows) and on Windows itself.

## What gets built

IPXWrapper is a set of **32-bit** Windows binaries, whatever system they are
built on:

| File | Purpose |
| --- | --- |
| `ipxwrapper.dll` | the IPX/SPX implementation |
| `wsock32.dll`, `mswsock.dll` | stand-ins for the system DLLs of the same name, which pass the calls on to `ipxwrapper.dll` |
| `dpwsockx.dll` | DirectPlay service provider for IPX |
| `ipxconfig.exe` | the configuration tool |
| `dplay-setup.exe` | registers the DirectPlay service provider |

They have to be 32-bit because the programs they are loaded into are, and
because part of the code (the stub functions generated by `mkstubs.pl`) is
32-bit x86 assembly. A 64-bit build is not possible. This is why a toolchain
*targeting* 32-bit Windows (`i686-w64-mingw32`) is needed, even on a 64-bit
system.

## Required tools

| Tool | Used for |
| --- | --- |
| MinGW-w64 GCC for the target `i686-w64-mingw32` (includes `windres`) | compiling and linking |
| GNU Make | running the build (`Makefile`) |
| NASM | assembling the generated stub functions |
| Perl | generating the stub functions (`mkstubs.pl`) |
| Git | getting the source code |
| zip (optional) | only for `make dist` |

Nothing else needs to be installed. The WinPcap headers and all other third
party code are included in the repository.

## Setting up the environment

### Linux

Debian, Ubuntu and derivatives:

```
sudo apt update
sudo apt install git make nasm perl zip gcc-mingw-w64-i686
```

Fedora:

```
sudo dnf install git make nasm perl zip mingw32-gcc
```

Arch Linux:

```
sudo pacman -S --needed git make nasm perl zip mingw-w64-gcc
```

Check that the cross compiler is there:

```
i686-w64-mingw32-gcc --version
```

### Windows

There are three ways. All of them give you a Unix-like shell in which the
build is done with the same command.

**Cygwin.** Run Cygwin's `setup-x86_64.exe` and select these packages in
addition to the defaults: `git`, `make`, `nasm`, `perl`, `zip` and
`mingw64-i686-gcc-core`. The same from the command line:

```
setup-x86_64.exe -q -P git,make,nasm,perl,zip,mingw64-i686-gcc-core
```

Despite its name, `mingw64-i686-gcc-core` is the compiler for 32-bit Windows
programs. It is a cross compiler like the one on Linux, called
`i686-w64-mingw32-gcc`. (Cygwin's normal `gcc` cannot be used: it builds
programs which depend on the Cygwin DLL.)

**MSYS2.** Install MSYS2 from <https://www.msys2.org>, open the **"MSYS2
MINGW32"** shell from the start menu (not "UCRT64" or "MINGW64", those build
64-bit programs) and install the tools:

```
pacman -S --needed git make nasm perl zip mingw-w64-i686-gcc
```

**WSL.** Install the Windows Subsystem for Linux with a distribution such as
Ubuntu (`wsl --install` in an administrator terminal), then follow the Linux
instructions above inside it.

## Getting the source

```
git clone https://github.com/solemnwarning/ipxwrapper.git
cd ipxwrapper
```

## Compiling

### Linux, Cygwin and WSL (cross-compiling)

Tell the Makefile the name of the cross toolchain using `HOST`:

```
make HOST=i686-w64-mingw32
```

The six files listed at the top appear in the current directory. `-j4` (or
however many CPU cores there are) speeds the build up.

### MSYS2 (MINGW32 shell)

Here the compiler is the native one of the environment, so no `HOST` is given:

```
make CC=gcc
```

### Variations

| Command | Effect |
| --- | --- |
| `make HOST=… clean` | delete everything that was built |
| `make HOST=… DEBUG=1` | keep debug symbols in the binaries (they are stripped by default) |
| `make HOST=… VERSION=0.8.0` | set the version shown in the log file (default: `git`) |
| `make HOST=… VERSION=0.8.0 dist` | additionally create `ipxwrapper-0.8.0.zip` (binaries) and `ipxwrapper-0.8.0-src.zip` (sources) |
| `make HOST=… ipxconfig.exe` | build a single file |

(For MSYS2 replace `HOST=…` by `CC=gcc`.)

After changing a header file a normal `make` is enough, dependencies are
tracked automatically (in the directory `.d`).

Two warnings about a redefinition of `INTERFACE` in `src/directplay.c` are
expected with current MinGW-w64 headers and harmless.

## Trying the result

Copy `ipxwrapper.dll`, `wsock32.dll`, `mswsock.dll` and `dpwsockx.dll` into the
directory of the program which is to use them, and run `ipxconfig.exe` to
change settings. See `readme.txt`.

To use a DOSBox IPX server without touching the registry, put a file named
`ipxwrapper.ini` next to the DLLs. `ipxwrapper.ini.example` describes all
settings, including the ones for IPv6.

## Tests

### Unit tests

The unit tests are small Windows programs which print their results in TAP
format:

```
make HOST=i686-w64-mingw32 tests/addr.exe tests/addrcache.exe tests/ethernet.exe \
    tests/ipver.exe tests/ratelimit.exe tests/spx.exe
```

Run them on Windows, or under Wine on Linux. Wine must be able to run 32-bit
programs; on Debian/Ubuntu:

```
sudo dpkg --add-architecture i386
sudo apt update
sudo apt install wine wine32:i386

wine tests/ipver.exe
```

The last line of the output reads `# All … tests successful or skipped` if
everything is fine.

### Trying the DOSBox encapsulation by hand

`make HOST=i686-w64-mingw32 test-prep` builds some command line tools into
`tools/` and copies the DLLs there. With an `ipxwrapper.ini` in `tools/`
pointing to a DOSBox IPX server, two terminals are enough to see packets
flowing (on Linux prefix the commands with
`WINEDLLOVERRIDES="wsock32,mswsock=n,b" wine`, so that Wine uses the DLLs just
built rather than its own):

```
ipx-recv.exe -b 00:00:00:00 00:00:00:00:00:00 4444
ipx-send.exe -b -d hello 00:00:00:00 FF:FF:FF:FF:FF:FF 4444
```

Add `logging = debug` to `ipxwrapper.ini` and have a look at `ipxwrapper.log`
to see which server address and IP version were used.

### The full test suite

The complete test suite (`tests/*.t`) needs a dedicated setup of a Linux and a
Windows machine connected by two networks. It is described in `readme.dev.txt`.
